λProlog over your knowledge graph: hypothetical questions, checks and rules

Datalog and N3 are first-order: rules over facts. λProlog is a logic programming language with higher-order rules, local assumptions (=>), fresh names (pi), cut and negation. oxilite runs λProlog programs with lean-elpi, the ELPI dialect implemented in Lean 4. Programs read the store through two host builtins and can answer goals, report violations, or add conclusions to the graph.

A guide · Every program and result on this page comes from the test suite (elpi.rs) or from the oxilite command line

Setup

The engine is a native library, libleanelpi, which carries the Lean runtime. It is built for macOS and Linux. Build it from lean-elpi, point LEANELPI_DIST at it, and turn the feature on:

git clone https://github.com/Volland/lean-elpi && cd lean-elpi && scripts/build-ffi.sh
export LEANELPI_DIST=$PWD/dist

cargo add oxilite --features elpi-native                  # Rust
cargo install oxilite-cli --features elpi                 # the command line

Without the library oxilite still builds: the elpi feature on its own gives you the API, and every run returns ElpiError::Unsupported.

1. The store, as λProlog sees it

A program reads the store through two builtins. Each call is answered by one pattern scan whose pattern is made of the call's bound arguments, so a goal about Ada reads Ada's triples, not the whole graph.

BuiltinAnswers
ox.triple S P OThe triples of the scope, graphs merged, each one once
ox.quad S P O GThe quads, with default-graph for the default graph

ELPI is typed, so RDF terms are values of a type term:

RDFλProlog
IRI(iri "http://example.org/ada")
string(str "Ada")
xsd:integer, xsd:double(num 36), (dbl 1.5), as native ELPI numbers, so arithmetic works
language-tagged string(lang "chat" "fr")
any other literal(lit "2026-11-03" "http://www.w3.org/2001/XMLSchema#date")
blank node(bnode "b0")

2. Goals

% family.elpi
pred parent o:term, o:term.
parent X Y :- ox.triple X (iri "http://example.org/parent") Y.

pred anc o:term, o:term.
anc X Y :- parent X Y.
anc X Z :- parent X Y, anc Y Z.
$ oxilite elpi -l family.db -f family.elpi --goal 'anc (iri "http://example.org/ada") Y'
Y
<http://example.org/bob>
<http://example.org/cy>
<http://example.org/dan>
3 solution(s), 6 row(s) read

Bindings that are RDF terms come back as RDF terms, IRIs here. Anything else ELPI can build, such as lists, numbers or λ-terms, comes back as ELPI prints it. Higher-order library predicates work as usual:

$ oxilite elpi -l family.db -f family.elpi \
    --goal 'std.findall (anc (iri "http://example.org/ada") Y) L, std.length L N'
L                                                       N
[anc (iri ".../ada") (iri ".../bob"), anc ... ]        3

Numbers are numbers. A stored xsd:integer binds an ELPI int:

pred adult o:term.
adult P :- ox.triple P (iri "http://example.org/age") (num A), A >= 18.

3. Hypothetical questions

This is what λProlog adds over Datalog and N3. H => G proves G with H assumed, and only while proving it. "If Dan had a child Eve, would Eve be Ada's descendant?"

$ oxilite elpi -l family.db -f family.elpi --goal \
  '(parent (iri "http://example.org/dan") (iri "http://example.org/eve") => anc (iri "http://example.org/ada") (iri "http://example.org/eve"))'
true

$ oxilite elpi -l family.db -f family.elpi --goal \
  'anc (iri "http://example.org/ada") (iri "http://example.org/eve")'
false

The assumption is never written; the test checks the store has the same size before and after. pi x\ … introduces a fresh name, so you can ask about "some new child of Dan" without making one up:

$ oxilite elpi -l family.db -f family.elpi --goal \
  'pi x\ (parent (iri "http://example.org/dan") x => anc (iri "http://example.org/ada") x)'
true

That is how you ask "what if" of a knowledge graph: try a change before you make it, or check that a policy holds for any new member of a class.

4. Checks

A program reports violations by defining ox.violation Severity Name Message Focus, with error or warning and a list of the terms it is about:

ox.violation error "missing-name" "a person needs a name" [P] :-
  ox.triple P (iri "http://www.w3.org/1999/02/22-rdf-syntax-ns#type") (iri "http://example.org/Person"),
  not (ox.triple P (iri "http://example.org/name") _).

ox.violation warning "minor" "a person under 18" [P] :-
  ox.triple P (iri "http://example.org/age") (num A), A < 18.
$ oxilite elpi -l family.db -f family.elpi --check
warning   minor          a person under 18       <http://example.org/bob>
error     missing-name   a person needs a name   <http://example.org/bob>
2 violation(s)
$ echo $?
1

The exit status is 1 when any violation is an error, so --check works as a gate in CI. From Rust, store.elpi_check(program)? returns the same list. SHACL is still the standard way to describe shapes. Checks are for rules SHACL can't easily express: recursive ones, ones that use hypotheticals, or ones that compute.

5. Conclusions into the graph

A program says what to store by defining ox.conclude (triple S P O):

ox.conclude (triple X (iri "http://example.org/ancestorOf") Y) :- anc Y X.
$ oxilite elpi -l family.db -f family.elpi --materialize
6 inferred triple(s) (producer elpi, 12 row(s) read)

$ oxilite query -l family.db --inferred -q \
  'PREFIX ex: <http://example.org/> SELECT ?x WHERE { ?x ex:ancestorOf ex:ada }'

Conclusions go into the same inference table that OWL 2 RL, Datalog and N3 write to, attributed to the producer elpi (or the one you name). SPARQL, Cypher and Datalog see them with include_inferred. Each run replaces its producer's earlier conclusions. A conclusion that is not a storable triple, such as one with a literal subject, is counted and skipped.

The takeaway. λProlog brings a full logic programming language to the graph. It can ask what would follow from a change before you make it, check rules that need recursion or computation, and add conclusions that every other query language reads. It only reads the triples it asks for.
